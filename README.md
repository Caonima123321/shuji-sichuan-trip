# 蜀迹 · 四川旅游规划 —— 多人协作版

一个可以在浏览器里用的四川旅游规划应用：**游客自己拼路线、看实时费用、按 1/3/7 日挑推荐路线**，
并且支持**多人同时编辑同一条路线**（实时同步）。

> 课程作业衍生项目 · 客群定位：高校在校大学生 · 路线全部在四川省内

## 在线地址（已部署）

**https://shuji-collab.onrender.com**

打开即用，**不限网络** —— 不同 WiFi、不同城市、手机流量都能进同一个房间协作。

> Render 免费实例闲置约 15 分钟会休眠，**第一次打开需等 30~60 秒**唤醒。
> 演示前先自己访问一次预热即可。

---

## 功能

**规划**
- 25 个四川景点，按城市分组，点一下加入行程
- 1 日 / 3 日 / 7 日共 8 条推荐路线，每条都有实景图与里程
- 出发地、天数、人数可调，天数会与推荐路线自动对齐

**费用**
- 六项成本实时拆到人：大交通、包车、住宿、餐饮、门票景交、体验项目
- 显示成本、报价、毛利率，与课程成本表可对照
- 人数变化时自动重算人均摊销

**行囊**
- 29 项装备清单，分 6 组，可勾选

**多人协作**（后端）
- 房间号机制：填名字 + 房间号即可加入同一份行程
- 实时同步：谁加了哪个景点、谁改了天数，其他人立刻看到
- 在线成员头像 + 协作记录流水
- **房间密码 + 三种角色**：主持人 / 可编辑 / 只读，越权操作在服务端被拒
- **三级降级**：WebSocket → SSE → HTTP 轮询，校园网拦了 WebSocket 也能用

## 角色与权限

房间密码是**一个密码、三种角色**。加入时在密码前加前缀即可：

| 输入 | 角色 | 能做什么 |
|---|---|---|
| `host:密码` | 主持人 | 全部权限，另可清空行程、设置/修改房间密码 |
| `edit:密码` | 可编辑 | 加/删景点、改天数人数、勾选清单 |
| `密码`（不加前缀） | 可编辑 | 同上，给不想记前缀的人用 |
| `view:密码` | 只读 | 只能看，不能改 |

**主持人怎么设置密码：** 加入房间后，在「我的 → 多人协作」里点「设置密码」。
设好之后，把带前缀的密码分别发给组员即可。留空则关闭密码。

> 前缀只是「请求的角色」，**不参与密码校验**。所以同一房间可以发三个不同的
> 前缀给三个人，而密码本体只有一个——不用为每个角色单独设密码。

**越权是服务端拦的，不是靠前端自觉。** 只读成员即使绕过界面直接调接口，
服务端也会返回 403。前端另外做了两层拦截（点击护栏 + 函数内校验），
只是为了体验更好，不是安全边界。

## 三级降级

```
WebSocket  ──失败3次──▶  SSE 推送  ──失败3次──▶  HTTP 轮询  ──▶  断开并提示重连
（最快，双向）          （服务器推送）         （1.2 秒一次）
```

部分校园网和公司代理会拦 WebSocket。这时会自动切到 SSE（Server-Sent Events，
同样是服务器主动推送，延迟低得多）；SSE 也被拦才退到轮询。

**应用是在线优先的**：后端地址默认已指向线上实例，打开页面填个名字和房间号就能协作，
不需要自己配任何东西。三条通道都连不上时，页面会显示断线状态，但已加载的
推荐路线、费用测算这些内容照常能看（数据在本地，不依赖网络）。

「我的 → 多人协作」里的状态点颜色对应通道：

| 颜色 | 含义 |
|---|---|
| 🟢 绿 | WebSocket 或 SSE，实时同步中 |
| 🟡 黄 | 轮询同步中（弱网兜底） |
| 🔴 红 | 连接已断开 |

## 部署

### 部署到 Render（推荐，一个服务搞定前后端）

1. 把本仓库推到 GitHub
2. Render 控制台 → **New** → **Blueprint** → 选中本仓库
3. Render 会读取 `render.yaml` 自动创建服务，等 1-2 分钟构建完成
4. 打开 Render 给的地址即可，**协作开箱可用**

> 注：Render 的 Blueprint 接口目前是 early access，控制台走 **New → Blueprint** 可以，
> 但 API 直连会返回 404。用 API 建服务的话走 `POST /v1/services`。

也可以不用 Blueprint，手动建 **Web Service**：

| 配置项 | 值 |
|---|---|
| Runtime | Python |
| Build Command | `python --version` |
| Start Command | `python server.py` |
| Health Check Path | `/health` |

> 服务只依赖 Python 标准库，**没有 requirements.txt 也能构建成功**。
> WebSocket 是手写实现（RFC 6455），HTTP 轮询与 WebSocket 共用同一个端口。

#### 免费版注意事项

- **冷启动**：免费实例闲置约 15 分钟会休眠，下次访问需等 30-60 秒唤醒。演示前先访问一次预热。
- **状态不持久**：容器文件系统是临时的，房间数据默认只在内存里，重启即清空。
  想让房间活过重启，可挂载持久磁盘并把 `SHUJI_STORE` 指到磁盘路径（免费版不支持磁盘）。

### 可选：前端另放一份到 GitHub Pages

线上服务本身就同时托管前端，所以这一步**不是必须的**，只是多一个入口。

1. 仓库 Settings → Pages → Source 选 `main` 分支 `/static` 目录
2. 打开 Pages 地址即可 —— 后端地址已内置默认值，不用手填

> 想换后端，三种方式（优先级从高到低）：
> 界面里手填 > `static/shuji.json` > 代码里的 `LIVE_BACKEND` 常量。

> GitHub Pages 是 HTTPS，后端也必须是 HTTPS（Render 默认就是）。
> 混用 http 后端会被浏览器拦截，这是正常的。

## 协作是怎么实现的

没有用任何第三方库和服务，全部跑在自己的后端上（**只依赖 Python 标准库**）。

**服务端权威模型。** 客户端不自己做合并，所有写操作都发给服务端，
服务端校验权限、应用、再把最新状态广播给房间内所有人。
这样两个人同时操作不会互相覆盖，越权也拦得住。

**传输层三通道。**
- 主通道：WebSocket（`RFC 6455` 手写实现——握手、掩码帧编解码、ping/pong 保活）
- 次通道：SSE（`/api/stream`，服务器推送，带心跳防代理超时）
- 兜底通道：HTTP 轮询

**为什么不用 long-polling？** 延迟比 SSE 高，且连接开销大。
SSE 是单向的，但这个场景里客户端→服务端只有零星几个写操作走 HTTP POST 就够，
推送走 SSE 完全够用。

**状态粒度。** 只同步行程本身（选了哪些景点、几天、几人、勾了哪些清单），
不同步「当前看哪个页签」，避免互相抢视图。

**任意网络都能协作。** 部署在公网，就是一个普通 HTTPS 站点，
任何人都能访问 —— 不需要内网穿透、不需要同一个 WiFi，也不依赖任何局域网。
前端会按页面协议自动选连接方式：

| 页面协议 | 连后端用 |
|---|---|
| `https://` | `wss://`（加密长连接） |
| `http://` | `ws://` |

**换后端地址不用改代码。** 四种方式，优先级从高到低：

1. 界面上「我的 → 多人协作 → 后端地址」手填（存 localStorage）
2. `static/shuji.json` 里的 `backend` 字段（后端上，改这一个文件即可）
3. 代码里的 `LIVE_BACKEND` 常量（内置兜底，默认就是线上实例）
4. `file://` 打开时以上都不适用 → 退回与页面同源

前三级的意义在于：**即使线上后端挂了、`shuji.json` 读不到，前端仍然知道该连哪里**，
不会退化成"没地方连"。

**密码怎么存的。** 只存 `sha256("shuji::" + 密码)`，不存明文；
房间密码本身不参与传输（加入时用密码换一个随机令牌，之后凭令牌通信）。
改密码会让所有旧令牌立即失效。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回 `ok` |
| GET | `/api/auth?room=CODE&pw=P` | 用密码换令牌与角色；密码错返回 401 |
| GET | `/api/room?room=CODE` | 读取房间状态、版本号、在线成员 |
| GET | `/api/poll?room=CODE&v=N` | 轮询；版本号大于 N 时才返回状态 |
| GET | `/api/stream?room=CODE&token=T` | SSE 通道 |
| POST | `/api/op` | 提交操作（`{"room","who","op","id","token"}`）；越权返回 403 |
| WS | `/?room=CODE&name=X&token=T` | 实时通道（也可用 `pw=` 直接认证） |

WebSocket 消息格式见 `server.py` 顶部注释。

所以同一套测试既能测本地，也能测线上部署。

### 测试里踩过的坑，都记下来了

**1. WebSocket 客户端是手写的。** 环境里没有 `websockets` 库，
`test_collab.py` 用标准库自己实现了握手、掩码帧编解码，
顺带就把协议实现本身也验证了。

**2. `const` 不会挂到 `window`。** 主脚本写的是 `const COLLAB = {...}`，
这是词法绑定，父页面读 `iframe.contentWindow.COLLAB` 只会拿到 `undefined`。
`test_roles.py` 因此改成往 iframe 里注入 agent，用 postMessage 通信。

**3. 注入的 agent 源码里含 `</script>` 字面量。** 直接拼进父页面的 `<script>` 里，
HTML 解析器会在那里提前闭合脚本，**整个 harness 静默失效**——不报错，只是不动。
正确做法是 `json.dumps(...).replace("</", "<\\/")`。

**4. `--virtual-time-budget` 会快进 `setTimeout`。** 早期版本用它做「等 2 秒再操作」，
结果 2 秒瞬间过去，客户端还没握手完就开始发指令，测试假失败。
现在改成轮询等真实状态，不靠猜时间。

**5. 别给 `urllib` 再套一层 chunked 解码。** 线上响应带
`Transfer-Encoding: chunked`，我以为要自己解帧，就写了个解码器 ——
结果 0 帧。实测 `resp.read(1)` 返回的是 `b'd'`（`data:` 的 d），
说明 **urllib 在 `resp.chunked=True` 时已经自动解好了**，我又套一层等于把正文当帧头解析。

**6. socket 打开 ≠ 入房完成。** 角色和令牌是服务端在 `welcome` 帧里下发的。
只等 `readyState === 1` 就取快照，会拿到过时的空角色 ——
本地毫秒级差异看不出来，跨公网 2.9 秒延迟下立刻暴露。改成等 `COLLAB.token` 就位。
